## 🔥 **EXPLICACIÓN ESPECÍFICA: Sintaxis de Relaciones**

### **¿Qué significa cada parte?**

```python
pet: Mapped["Pet"] = relationship("Pet", back_populates="medical_info")
```

**DESGLOSE COMPLETO:**

#### **1. `pet:`**
- Nombre del atributo/propiedad
- Como accedes: `medical_info.pet`
- No es una columna en la DB, es una relación

#### **2. `Mapped["Pet"]`**
- **`Mapped`** → Le dice a SQLAlchemy "esto es una relación"
- **`"Pet"`** → Con comillas porque Pet se define después (referencia circular)
- **Type hint:** "Este atributo será un objeto de la clase Pet"

#### **3. `relationship("Pet")`**
- **`relationship`** → Función de SQLAlchemy para crear relaciones
- **`"Pet"`** → Nombre de la clase con la que se relaciona (como string)
- **Crea la conexión lógica** entre las tablas

#### **4. `back_populates="medical_info"`**
- **Le dice a SQLAlchemy:** "En la clase Pet hay un atributo llamado medical_info"
- **Crea relación bidireccional:** pet.medical_info ↔ medical_info.pet
- **Mantiene sincronización:** Si cambias uno, el otro se actualiza automáticamente

### **¿Por qué comillas en `"Pet"`?**

```python
# ❌ PROBLEMA: Referencia circular
class Pet(Base):
    medical_info: Mapped["MedicalInfo"] = relationship("MedicalInfo")  # MedicalInfo no existe aún

class MedicalInfo(Base):
    pet: Mapped[Pet] = relationship(Pet)  # Pet ya existe, pero Python se confunde
```

```python
# ✅ SOLUCIÓN: Usar strings
class Pet(Base):
    medical_info: Mapped["MedicalInfo"] = relationship("MedicalInfo")  # String = referencia futura

class MedicalInfo(Base):
    pet: Mapped["Pet"] = relationship("Pet")  # String = referencia ya definida
```

### **Tipos de relaciones:**

#### **1. Relación Uno-a-Uno (uselist=False)**
```python
# En Pet:
medical_info: Mapped["MedicalInfo"] = relationship(
    "MedicalInfo", 
    uselist=False  # ← UNO: pet.medical_info es UN objeto
)

# En MedicalInfo:
pet: Mapped["Pet"] = relationship("Pet")  # ← UNO: medical_info.pet es UN objeto
```

#### **2. Relación Uno-a-Muchos (default)**
```python
# En Pet:
documents: Mapped[List["Document"]] = relationship("Document")
#           ↑ List = MUCHOS: pet.documents es una LISTA

# En Document:  
pet: Mapped["Pet"] = relationship("Pet")
#    ↑ Sin List = UNO: document.pet es UN objeto
```

### **¿Qué hace back_populates?**

#### **Sin back_populates (PROBLEMÁTICO):**
```python
# En Pet:
medical_info: Mapped["MedicalInfo"] = relationship("MedicalInfo")

# En MedicalInfo:
pet: Mapped["Pet"] = relationship("Pet")

# PROBLEMA: Son relaciones separadas, no sincronizadas
pet.medical_info = mi_medical_info  # Se actualiza pet.medical_info
print(mi_medical_info.pet)          # None - no se sincronizó automáticamente
```

#### **Con back_populates (CORRECTO):**
```python
# En Pet:
medical_info: Mapped["MedicalInfo"] = relationship("MedicalInfo", back_populates="pet")

# En MedicalInfo:
pet: Mapped["Pet"] = relationship("Pet", back_populates="medical_info")

# CORRECTO: Sincronización automática
pet.medical_info = mi_medical_info  # Se actualiza pet.medical_info
print(mi_medical_info.pet)          # <Pet object> - se sincronizó automáticamente
```

### **Ejemplo práctico de uso:**

```python
# CREANDO REGISTROS RELACIONADOS

# Crear mascota
pet = Pet(name="Rex", breed="Labrador")

# Crear info médica
medical_info = MedicalInfo(
    medication="Vacuna antirrábica",
    allergies="Ninguna conocida"
)

# CONECTAR LA RELACIÓN
pet.medical_info = medical_info  # Asignas en una dirección

# AUTOMÁTICAMENTE se sincroniza la otra dirección:
print(medical_info.pet)  # <Pet object: Rex> - se asignó automáticamente

# O puedes asignar desde el otro lado:
medical_info.pet = pet   # Asignas desde medical_info
print(pet.medical_info)  # <MedicalInfo object> - se sincronizó automáticamente
```

### **Diferencia entre relationship y ForeignKey:**

```python
class MedicalInfo(Base):
    # FOREIGN KEY: Campo real en la DB que almacena el ID
    pet_id: Mapped[int] = mapped_column(Integer, ForeignKey("pets.id"))
    #       ↑ Columna real: almacena 1, 2, 3, etc.
    
    # RELATIONSHIP: Atributo Python para navegar entre objetos
    pet: Mapped["Pet"] = relationship("Pet", back_populates="medical_info")
    #    ↑ No es columna: te da el objeto Pet completo
```

### **Uso práctico:**

```python
# Con ForeignKey accedes al ID:
print(medical_info.pet_id)  # 5

# Con relationship accedes al objeto completo:
print(medical_info.pet.name)      # "Rex"
print(medical_info.pet.breed)     # "Labrador"  
print(medical_info.pet.weight)    # 25.5
```

### **Cascadas en relaciones:**

```python
# CON CASCADE: Eliminar automáticamente
documents: Mapped[List["Document"]] = relationship(
    "Document",
    cascade="all, delete-orphan"  # Si elimino pet, elimino sus documentos
)

# SIN CASCADE: Documentos quedan huérfanos
documents: Mapped[List["Document"]] = relationship("Document")
# Si elimino pet, los documentos siguen existiendo con pet_id inválido
```

### **Tabla resumen de sintaxis:**

| Sintaxis | Significado | Ejemplo |
|----------|-------------|---------|
| `Mapped["Clase"]` | Type hint con referencia futura | `owner: Mapped["User"]` |
| `relationship("Clase")` | Conexión con otra clase | `relationship("Pet")` |
| `back_populates="atributo"` | Sincronización bidireccional | `back_populates="pets"` |
| `uselist=False` | Relación uno-a-uno | Un pet = una info médica |
| `List["Clase"]` | Relación uno-a-muchos | Un pet = muchos documentos |
| `cascade="all, delete-orphan"` | Eliminar relacionados | Eliminar pet = eliminar documentos |

## 🔥 **EXPLICACIÓN ESPECÍFICA: Mapped[Optional[str]]**

### **¿Qué significa cada parte?**

```python
chip_number: Mapped[Optional[str]] = mapped_column(String(50))
```

**DESGLOSE COMPLETO:**

#### **1. `chip_number:`**
- Es el nombre del atributo/campo
- Como accedes al valor: `pet.chip_number`

#### **2. `Mapped[Optional[str]]`** 
- **`Mapped`** → Le dice a SQLAlchemy "esto es un campo de la tabla"
- **`Optional[str]`** → Type hint que significa "puede ser string o None"
- **`Optional[str]` = `Union[str, None]`** → Equivale a "str | None" en Python 3.10+

#### **3. `mapped_column(String(50))`**
- **`mapped_column`** → Función que define la columna real en la DB
- **`String(50)`** → Tipo de dato MySQL: VARCHAR(50)

### **Comparación: Obligatorio vs Opcional**

```python
# CAMPO OBLIGATORIO (no puede ser None)
name: Mapped[str] = mapped_column(String(100), nullable=False)
#     ↑ Sin Optional = siempre debe tener valor

# CAMPO OPCIONAL (puede ser None)  
chip_number: Mapped[Optional[str]] = mapped_column(String(50))
#            ↑ Con Optional = puede ser None
```

### **¿Qué pasa sin Optional?**

```python
# ❌ INCORRECTO - Dice que siempre tiene valor pero puede ser None
chip_number: Mapped[str] = mapped_column(String(50))  # Miente sobre el tipo

# En tu código:
pet = Pet(name="Rex")  # No das chip_number
print(pet.chip_number)  # None - pero el type hint dice que es str!

# Tu IDE se confunde:
pet.chip_number.upper()  # IDE no te advierte que puede ser None = ERROR
```

```python
# ✅ CORRECTO - Type hint honesto
chip_number: Mapped[Optional[str]] = mapped_column(String(50))

# En tu código:
pet = Pet(name="Rex")
if pet.chip_number:  # IDE sabe que puede ser None
    print(pet.chip_number.upper())  # Solo ejecuta si no es None
else:
    print("Sin chip")
```

### **Relación con nullable=True/False**

```python
# OBLIGATORIO: No puede ser None
name: Mapped[str] = mapped_column(String(100), nullable=False)
#     ↑ Sin Optional              ↑ No permite None en DB

# OPCIONAL: Puede ser None
chip_number: Mapped[Optional[str]] = mapped_column(String(50))
#            ↑ Con Optional                         ↑ nullable=True por defecto
```

### **Tabla de equivalencias:**

| Type Hint | mapped_column | Significado | Valor por defecto |
|-----------|---------------|-------------|-------------------|
| `Mapped[str]` | `nullable=False` | OBLIGATORIO | Error si no das valor |
| `Mapped[Optional[str]]` | `nullable=True` | OPCIONAL | None si no das valor |
| `Mapped[int]` | `nullable=False` | OBLIGATORIO | Error si no das valor |
| `Mapped[Optional[int]]` | `nullable=True` | OPCIONAL | None si no das valor |

### **Ejemplo práctico de la diferencia:**

```python
# CREANDO UNA MASCOTA

# Con campos obligatorios (sin Optional):
pet = Pet(
    name="Rex",      # ✅ Obligatorio - debe darse
    breed="Labrador", # ✅ Obligatorio - debe darse
    birth=date.today(), # ✅ Obligatorio - debe darse
    gender=Gender.MALE  # ✅ Obligatorio - debe darse
)

# Campos opcionales (con Optional):
# chip_number → None automáticamente
# weight → None automáticamente  
# avatar → None automáticamente

print(pet.chip_number)  # None
print(pet.weight)       # None
print(pet.avatar)       # None
```

### **¿Por qué es importante esto?**

1. **Tu IDE te ayuda mejor:**
   ```python
   # Con Optional, tu IDE te advierte:
   if pet.chip_number:  # ← IDE: "Bien, verificas si es None"
       print(pet.chip_number.upper())
   
   # Sin Optional, tu IDE no sabe:
   print(pet.chip_number.upper())  # ← IDE: "Debería funcionar" → ERROR en runtime
   ```

2. **Código más seguro:**
   ```python
   # Con type hints correctos puedes usar herramientas como mypy
   # que detectan errores antes de ejecutar
   ```

3. **Documentación viva:**
   ```python
   # Solo mirando el type hint sabes:
   chip_number: Mapped[Optional[str]]  # ← "Puede ser None"
   name: Mapped[str]                   # ← "Siempre tiene valor"
   ```

## 🔥 **SECCIÓN 5: RELACIONES**

```python
# Línea 51
owner: Mapped["User"] = relationship("User", back_populates="pets")  # Relación con el propietario
```
**QUÉ HACE:** Conecta pet.owner para acceder al propietario
**DESGLOSE:**
- `"User"` → String porque User se define en otro archivo
- `back_populates="pets"` → User también tiene una relación pets que apunta aquí
**RESULTADO:** `pet.owner` te da el usuario, `user.pets` te da sus mascotas

```python
# Líneas 53-58
medical_info: Mapped["MedicalInfo"] = relationship(
    "MedicalInfo", 
    back_populates="pet", 
    cascade="all, delete-orphan",  # Elimina la info médica si se elimina la mascota
    uselist=False  # Especifica que es una relación uno-a-uno
)
```
**QUÉ HACE:** Relación uno-a-uno con información médica
**DESGLOSE:**
- `cascade="all, delete-orphan"` → Si eliminas pet, elimina su medical_info
- `uselist=False` → pet.medical_info es UN objeto, no una lista
**SIN uselist=False:** pet.medical_info sería una lista con un elemento

```python
# Líneas 60-65
documents: Mapped[List["Document"]] = relationship(
    "Document", 
    back_populates="pet", 
    cascade="all, delete-orphan"  # Elimina todos los documentos si se elimina la mascota
)
```
**QUÁ HACE:** Relación uno-a-muchos con documentos
**DESGLOSE:**
- `List["Document"]` → pet.documents es una lista de documentos
- `cascade="all, delete-orphan"` → Si eliminas pet, elimina todos sus documentos
**SIN cascade:** Los documentos se quedan huérfanos en la DB


**QUÉ HACE:** Relación uno-a-muchos con eventos, ordenados por fecha

```python
from sqlalchemy.orm import validates
from datetime import date

class Pet(Base):
    # ... campos existentes ...
    
    @validates('weight')
    def validate_weight(self, key, weight):
        if weight is not None and weight <= 0:
            raise ValueError("El peso debe ser mayor a 0 kg")
        if weight is not None and weight > 200:
            raise ValueError("El peso parece demasiado alto (máximo 200 kg)")
        return weight
    
    @validates('birth')
    def validate_birth(self, key, birth_date):
        if birth_date > date.today():
            raise ValueError("La fecha de nacimiento no puede ser en el futuro")
        
        # Calcular edad máxima (30 años para ser realista)
        max_age_date = date.today().replace(year=date.today().year - 30)
        if birth_date < max_age_date:
            raise ValueError("La fecha de nacimiento parece demasiado antigua")
        
        return birth_date
    
    @validates('name')
    def validate_name(self, key, name):
        if not name or len(name.strip()) == 0:
            raise ValueError("El nombre no puede estar vacío")
        if len(name.strip()) > 100:
            raise ValueError("El nombre no puede tener más de 100 caracteres")
        return name.strip()
```

### **Errores típicos y cómo manejarlos**
```python
from sqlalchemy.exc import IntegrityError, SQLAlchemyError

def create_pet_with_error_handling(pet_data):
    session = SessionLocal()
    try:
        pet = Pet(**pet_data)
        session.add(pet)
        session.commit()
        session.refresh(pet)
        return pet
        
    except IntegrityError as e:
        session.rollback()
        error_msg = str(e.orig)
        
        if "foreign key constraint" in error_msg.lower():
            raise ValueError("El propietario especificado no existe")
        elif "duplicate entry" in error_msg.lower():
            raise ValueError("Ya existe una mascota con esos datos")
        elif "cannot be null" in error_msg.lower():
            raise ValueError("Faltan campos obligatorios")
        else:
            raise ValueError(f"Error de integridad de datos: {error_msg}")
    
    except ValueError as e:
        # Errores de validación custom
        session.rollback()
        raise e
    
    except SQLAlchemyError as e:
        session.rollback()
        raise RuntimeError(f"Error de base de datos: {e}")
    
    except Exception as e:
        session.rollback()
        raise RuntimeError(f"Error inesperado: {e}")
    
    finally:
        session.close()

# Ejemplo de uso
try:
    pet = create_pet_with_error_handling({
        "user_id": 999,  # ❌ Usuario no existe
        "name": "Rex",
        "birth": date.today(),
        "breed": "Labrador",
        "gender": Gender.MALE
    })
except ValueError as e:
    print(f"Error de datos: {e}")
except RuntimeError as e:
    print(f"Error del sistema: {e}")
```

```python
def get_user_pets_summary(user_id: int):
    session = SessionLocal()
    try:
        from sqlalchemy import func
        
        # Consulta con agregaciones
        result = session.query(
            User.name,
            func.count(Pet.id).label('total_pets'),
            func.avg(Pet.weight).label('avg_weight'),
            func.count(Event.id).label('total_events')
        )\
        .join(Pet, User.id == Pet.user_id)\
        .outerjoin(Event, Pet.id == Event.pet_id)\
        .filter(User.id == user_id)\
        .group_by(User.id, User.name)\
        .first()
        
        if result:
            return {
                "owner_name": result.name,
                "total_pets": result.total_pets,
                "average_weight": float(result.avg_weight) if result.avg_weight else 0,
                "total_events": result.total_events
            }
        
        return None

        session.close()

def get_upcoming_events(days_ahead: int = 7):
    session = SessionLocal()
    try:
        from datetime import timedelta
        
        end_date = date.today() + timedelta(days=days_ahead)
        
        events = session.query(Event)\
            .join(Pet)\
            .filter(Event.date >= date.today())\
            .filter(Event.date <= end_date)\
            .filter(Event.is_completed == False)\
            .options(joinedload(Event.pet))\
            .order_by(Event.date, Event.time)\
            .all()
        
        return [{
            "id": event.id,
            "name": event.name,
            "date": event.date.isoformat(),
            "time": event.time,
            "pet_name": event.pet.name
        } for event in events]
        
    finally:
        session.close()
```
